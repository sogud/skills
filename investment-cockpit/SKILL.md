# Investment Cockpit

读取同一份持仓与历史记录，按问题调用必要的数据能力，区分资产配置、交易研究和学习。不依赖特定看盘软件或另建持仓数据库。

## 启动

遵循根 AGENTS 的投资路由；已取得有效 context 时直接继续，不重复调用，也不硬编码 route ID。只按当前请求读取：

| 请求 | 必要输入 | 完成条件 |
|---|---|---|
| 单只价格、指标等数据查询 | 标的、字段；匹配的数据 Skill | 数值、来源、时间、口径；不读持仓或日报，不生成操作卡 |
| 更新持仓 | 用户新数据 + 根 AGENTS 指定的 `investment-ledger/`，按需查 Holdings / Accounts / Transactions / Decisions | 追加带日期与来源的记录，保留历史；待确认交易不算已成交 |
| 确认或调整交易规则 | 当前明确确认、账本Decisions中相关已确认规则，以及工作流“短线持仓与规则确认” | 记录市场、周期及修订关系；同步受影响的流程正文，不重复询问已确认选项，不把规则确认当成交 |
| 资产配置、基金/黄金调仓 | 相关账户确认数据、`knowledge/Invest/Reference/个人投资原则.md`；必要的资金用途、产品与费用信息 | 区分配置偏离与短期价格判断；缺金额时只给条件或计算方法 |
| 完整复盘 | `投资每日复盘与学习工作流.md`、`投资日报模板.md`（均在 `knowledge/Invest/`），账本Decisions中最近相关待复核判断；涉及本人组合再读对应账户表 | 先复核旧条件，再记录本次变化、动作与失效条件；只填写相关窗口 |
| 交易研究、短线候选 | 标的范围、周期、当前数据；A 股再读 `knowledge/Invest/A股短线训练账户规则.md`；涉及本人操作再读个人原则与相关账户 | 先判断是否仅供观察/纸面研究；满足数据与账户条件才给可执行操作卡，不自动恢复真实短线预算 |
| 看盘学习、解释图表 | 目标图表的品种、来源、周期和时间；学习方法按需读工作流“学习与复核” | 一个概念、图上证据、反例和理解检查；无操作请求不读账户、不生成买卖卡 |
| 历史策略实验 | manifest 中量化 Project 对应的 context 与项目规则 | 在量化项目执行；不拿历史示例回答当日买卖 |

持仓以用户截图或明确确认的数据优先，公开行情不能覆盖实际份额和现金。不默认加载全部历史。若规则要求暂停，说明具体缺失条件；缺某字段不妨碍已获证据部分继续分析。

模式选择与复核细则只在 `knowledge/Invest/投资每日复盘与学习工作流.md` 维护；输出字段只在 `knowledge/Invest/投资日报模板.md` 维护。当前用户明确要求优先于旧偏好，但“教我交易”不等于修改个人投资原则或授权实际交易。

## 数据路由

需要外部数据或直接读图时，先读 `knowledge/Invest/Reference/Agent行情数据工作流.md`，按其中市场/字段路由、能力状态和失败处理选择工具；此 Skill 不另设供应商优先级。只检查本次会用的能力，不做全工具健康扫描。

- 当前判断使用新鲜证据；已取得且仍符合本次时点与口径的数据不重复抓取。历史成功和技能存在不等于本次数据可用。
- 使用 Longbridge 美股 quote 做当前判断前，运行数据工作流的 `validate-us-quote`；读取字段检查及未验证项，不能把 `ok=true` 当交易建议授权。其他来源也须核对价格自身时间与时段，不能借用抓取时间或其它字段时间。
- 用户要求直接看 TradingView 时，读取 `tradingview-reader` 技能；按数据工作流的已授权桌面读取回退操作，不先让用户重复截图，不因缺插件自动安装或重启软件。
- 数据状态为 `observation_only` 或 `buy_card_allowed=false` 时，只交付观察结果与缺项，不通过更换工具绕过限制生成买入卡。单标的图表不能证明全市场覆盖或策略有效。
- 工具失败保留原因，按数据工作流限次回退；仍缺关键证据时停止该项结论，继续回答已有证据支持的部分。凭据和会话数据不写入报告。

### A 股主板过滤

无论候选来自华泰、Longbridge 还是其他来源，都不能只依赖模型识别板块。先把结构化 JSON 传给本 Skill 的确定性过滤器。从本 Skill 目录运行；其他目录使用脚本的绝对路径：

```bash
python3 scripts/filter_mainboard.py --input <候选结果.json>
```

过滤器只保留 `600/601/603/605` 开头的沪市 A 股与 `000/001/002/003` 开头的深市 A 股，并剔除名称以 `ST`、`*ST` 开头或含“退”的标的。无法解析代码的候选默认排除；过滤后的标的仍需检查停牌、涨跌停、流动性和重大事件风险。

## 分析与输出契约

日常复盘先按模板“一屏摘要”交付：旧判断状态、新证据、持仓含义与动作、一个学习点或下次检查条件；用户要求详细研究再展开。简单查询直接回答，不套摘要。证据区分：

- **Fact**：带数据时间和来源。
- **Inference**：由事实推导，写出关键证据。
- **Assumption**：尚未验证的前提。
- **Rumor**：原则上不用于交易动作；确需提及必须明确标记。

按问题选择必要情景，至少说明主要判断的反方或失效条件。概率可选；提供时注明主观估计或统计来源，只有互斥且穷尽的情景才合计 100%，不为填模板编造概率。不能承诺收益或声称某标的一定上涨。没有新鲜价格时，不给伪精确的入场价、止损价或目标价。

涉及操作建议时使用模板的条件化操作卡。精确金额、股数以及“减仓25%”这样的比例，都要能追溯到已确认账户、资金用途和风险预算或目标配置；收益预测不能代替这些输入。缺失时保留方向、触发/失效条件与计算方法，只问影响操作的关键缺项，不先填一个看似精确的数。数据仅供观察时不填写可执行买入金额或股数。配置调整说明偏离目标、费用和复核期限，不强造短线止损价；基金核对申赎、持有期费用与 QDII 延迟。

## 判断记录与复核

先读取最近相关且仍需检查的判断，不只按“昨天”找记录。复核状态、评分、期限和版本规则以工作流“判断记录与复核”及模板为准；未触发、未到期或证据不足不算成功。方向判断与条件交易的结果分开，建议、模拟和实际成交分开。没有可核对的旧记录时明确说明，不补造预测或收益。

## 写入规则

- 完整复盘、针对本人持仓的操作建议，以及有明确期限的新市场判断，在回答交付前把结构化判断和用户确认追加到根 AGENTS 指定账本的 Decisions；真实交易/申请写 Transactions，持仓和账户指标分别写 Holdings / Accounts。需要完整分析正文时才另写 Markdown 并关联 RecordID，不再为了记数字每天新建文件。账本读写、备份与校验遵循根 AGENTS。用户要求仅讨论、不保存时遵从，不宣称已记录。
- 同日更新只追加新版本、证据或复核，保留已冻结文字；跨日复核链接原判断，不复制或重写原文。无新证据不重复生成同一建议。简单查价、一般概念教学不自动保存日报，理解检查未收到回答就写待练习，不虚构学习结果。
- 从聊天补录时分别写原发言时间、实际补录时间和可核对来源，标注“补录，非事前文件冻结”；不能把缺失的历史内容补成已验证预测。
- 持仓更新、历史保留、币种和索引维护遵循根 AGENTS 的唯一规则；市场观点、建议和价格估算不改实际账户事实。CSV 字段解释在Schema，原文与来源在History/Sources；不重新导入旧Markdown覆盖人工更新。
- 四类记录统一使用根 AGENTS 指定的固定编辑工具，先预览再写入；新来源与交易修订也走同一工具。分析本人账户前按需运行账本status，检查各字段日期与缺项，不把历史Overview当作当前资金。具体输入、Current与修订规则只在根AGENTS和工具帮助中维护；不生成日更脚本或长期保留全表导出日志。清理单独取得授权，不因复盘完成自动删除证据或备份。

## 安全边界

- 本 Skill 只分析、记录和生成供用户手动执行的建议，不执行真实交易。
- 不因“账户已配置”自动读取账户。任何账户读取、自选修改或模拟交易都要求用户明确提出。
- 真实下单、改单、撤单不在本 Skill 能力范围内；禁止 `trade.*`、写入式 `api.post`、银行卡或资金划转操作，不自动安装软件、购买服务或创建定时任务。
