# Stage: Report Quality

交付前检查结论是否由本次证据支持。使用同一套研究标准，不把报告长度、工具数量或 HTML 外观当成研究有效性。

## 必须检查

- 原问题、市场、信息截至日期和判断期限明确。
- 关键事实引用原始披露、官方数据或有来源和日期的具体数据页面；搜索摘要、模型回答和本地笔记不是外部事实的原始证据。
- 数字口径一致：报告期、价格时段、币种、单位、GAAP/non-GAAP、估计/实际值分开。估值/公司优先级依赖的财务基线与可比基线不能缺失。
- 产业链/技术/供需结论有相应直接证据；“热度”不等于收入或供给约束。叙事来源未知时移除来源断言。
- 事实、推断、假设和缺失字段可区分；主论点有反方证据、失效条件与复核期限。
- 关键概念用读者能理解的语言解释，不为了模板虚构术语表、图表或量化概率。
- 先前判断按原期限和条件复核，保留未触发、未到期和错误判断。
- 研究评级不是买卖建议、命中率、收益保证或仓位依据。

## 缺项如何处理

逐项列出缺失事实、影响哪些结论和能取得的替代证据。删除或暂缓依赖缺项的判断，保留独立成立的结论；若核心问题无法回答，直接说明无法判断及需要的证据。已有授权内只读查询无需重复申请；新权限按宿主规则处理，不为完成报告自动购买或安装。

需要详细数字检查时读 `resources/data-rigor.md`；只有相关技术/商品论点才使用 `resources/research-tool-stack.md` 对应证据标准。不遍历全部渠道。

## 输出

默认将结论、证据/反方、缺项与复核条件写入同一篇 Markdown。可用 `templates/thesis-card.md` 记录可检验论点；不强制创建中间稿或重复正式报告。

研究质量可用 COMPLETE / LIMITED / BLOCKED 描述证据是否足以回答问题，不能转成股票评级或胜率。

只有明确要求 HTML 时，读取 `resources/report-visual-system.md`、`resources/citation-system.md` 和 `templates/report.html`。将原始出处做成可点击引用；图表注明源数据、单位、日期，提供文字说明。HTML 和 Markdown 应基于同一份研究，不产生第二套判断。
